1. OVERVIEW OF THE APPLICATION
================================================================================

CreditIQ is an AI-powered credit risk assessment platform built using Python
and Streamlit (a library that turns Python scripts into interactive web apps).

The application uses a pre-trained machine learning model (Random Forest with
200 decision trees) that was trained on the famous "German Credit Dataset"
containing 1,000 real-world loan applicants.

When a bank or credit analyst enters an applicant's financial and personal
information, the model:
  1. Predicts whether the applicant is a GOOD or BAD credit risk
  2. Provides a probability score (0–100%)
  3. Converts this to a credit score between 300 and 850 (similar to FICO)
  4. Categorises the applicant into Low / Medium / High risk tiers
  5. Generates personalized recommendations
  6. Produces a downloadable assessment report

The application also supports batch processing (scoring hundreds of applicants
at once by uploading a CSV file) and provides a rich analytics dashboard.

7. SECTION E — MODEL & DATASET LOADING (Lines 273–285)
================================================================================

LINE 276–278:
    @st.cache_resource
    def load_model():
        return joblib.load("credit_scoring_model.joblib")

    ─────────────────────────────────────────────────────────────────────────
    Defines a function that loads the trained machine learning model from
    the file "credit_scoring_model.joblib" on disk.

    @st.cache_resource is a Streamlit decorator that ensures this function
    runs ONLY ONCE when the app first starts, and then caches (stores) the
    result in memory. If it ran every time a user clicked a button, it would
    needlessly reload the model from disk, making the app slow.

    The model is a scikit-learn Pipeline containing:
      1. A ColumnTransformer (preprocessor) — handles data transformation
      2. A RandomForestClassifier (200 trees) — makes predictions

LINE 280–282:
    @st.cache_data
    def load_dataset():
        return pd.read_csv("german_credit_data.csv")

    ─────────────────────────────────────────────────────────────────────────
    Similarly loads the training dataset CSV file into memory.
    @st.cache_data caches data (like DataFrames) so it is only read
    from disk once. The dataset powers all the charts in the Analytics
    Dashboard, as well as the sidebar statistics.

LINE 284–285:
    model = load_model()
    df_ref = load_dataset()

    ─────────────────────────────────────────────────────────────────────────
    Calls both loading functions and stores their results in global
    variables (model and df_ref) so they are accessible throughout the
    entire application.

F1. compute_credit_score(prob_good)  —  Lines 296–298
────────────────────────────────────────────────────────
    def compute_credit_score(prob_good: float) -> int:
        return int(300 + (prob_good ** 0.7) * 550)

    Takes the model's probability of good credit (a number between 0.0
    and 1.0) and converts it to a credit score on a 300–850 scale,
    which mirrors the widely-used FICO credit score format.

    Formula explanation:
      - The minimum score is 300 (when probability = 0)
      - The maximum score is 850 (when probability = 1)
      - The exponent 0.7 applies a slight curve so that mid-range
        probabilities produce more spread-out scores, making the
        scoring feel more granular and realistic.
      - Example: 0.80 probability → score of approximately 718

F2. risk_tier(prob_good)  —  Lines 300–303
────────────────────────────────────────────────────────
    def risk_tier(prob_good: float) -> str:
        if prob_good >= 0.75: return "Low"
        if prob_good >= 0.45: return "Medium"
        return "High"

    Classifies an applicant into one of three risk categories based on
    their probability of being a good credit risk:
      ≥ 75%  →  Low Risk    (safe to approve)
      45–74% →  Medium Risk (requires review)
      < 45%  →  High Risk   (likely to decline)

F10. risk_factors_radar(input_dict)  —  Lines 462–500
────────────────────────────────────────────────────────
    Creates a spider/radar chart showing the applicant's profile
    across the 8 most important features.

    Each feature value is normalised to a 0–1 scale:
      0 = worst possible value for creditworthiness
      1 = best possible value for creditworthiness

    Normalisations applied:
      laufkont  : (value - 1) / 3        — checking account health
      hoehe     : 1 - (amount / 18000)   — less debt = better
      laufzeit  : 1 - (months / 72)      — shorter duration = better
      moral     : code / 4               — higher code = better history
      alter     : (age - 19) / 56        — older = more experience
      verm      : (code - 1) / 3         — better property = better
      sparkont  : (code - 1) / 4         — more savings = better
      beszeit   : (code - 1) / 4         — longer employment = better

    The radar shows instantly which dimensions of the applicant are
    strong or weak, giving credit officers a one-glance overview.

    to the model's output probability.

16. KEY CONCEPTS EXPLAINED (NON-TECHNICAL)
================================================================================

What is a Random Forest?
    A Random Forest is a machine learning algorithm that builds many
    decision trees (200 in this case) and combines their votes to make
    a prediction. Each tree is trained on a slightly different sample
    of the data, making the combined result more robust than any single
    tree. Think of it as asking 200 experts and going with the majority
    decision.

What is Probability?
    When the model returns "prob_good = 0.78", it means the model is
    78% confident this applicant will repay their loan. The remaining
    22% represents uncertainty.

What is a Threshold?
    The threshold determines when "78% confident" is enough to say
    "Approve". At 50% threshold, any probability above 50% = approve.
    At 70% threshold, only probabilities above 70% = approve.

What is Feature Importance?
    The model internally measures how often and how much each feature
    helped it make correct predictions during training. "Checking Account"
    at 16.1% means it is by far the single most useful piece of information.

What is the Credit Score (300–850 scale)?
    We convert the model's probability to this standard scale purely for
    familiarity. The formula is: 300 + (probability^0.7) × 550.
    This is an approximation of FICO-style scoring and provides an
    intuitive number for loan officers accustomed to credit scores.
